# Identity and Access

Identity realism is one of the strongest parts of the current product.

## Current identity surfaces

DataGen can generate:

- people and organizational structure
- user and service accounts
- groups and directory hierarchy
- hybrid and cloud identity stores
- generic containers such as domain, OU, tenant, and administrative-unit surfaces
- guest and external workforce populations

## Policy and targeting

The current policy model supports first-class policy objects, policy settings, and policy target links. This gives the world a believable configured-policy layer rather than only inferred outcomes.

Examples include:

- AD and GPO-style configured policies
- Entra and Intune-style policy records
- Azure-policy-style governance records
- Windows security-template and advanced-audit policy objects

### Windows security policy families

Every company carries a `Windows Security Template Baseline` and a `Windows Advanced Audit Policy Template`, holding privilege-rights assignments, advanced audit subcategories, and file and registry security descriptors in the vocabulary a security template export and a Group Policy audit backup actually carry.

Scenarios can additionally opt into the endpoint side. `infrastructure.effectiveSecurityConfigurationEndpointCount`, bounded between 0 and 250 and defaulting to 0, gives that many Windows endpoints per company a `LocalSecurityPolicy` object describing the configuration that machine carries, built from the template's own value for each setting. Only Windows endpoints receive one, because a local security policy is a Windows object.

These are separate policy objects from the friendly-named baselines DataGen already emitted, which are unchanged. See [Normalized Export](/integrations/normalized-export) for the canonical key forms, the value shapes, and how an endpoint policy joins back to its endpoint.

## Access evidence

DataGen intentionally separates access evidence from inferred effective access.

That means the generated world can include:

- delegation records
- policy apply evidence
- local admin or support-group evidence
- repository and collaboration permission evidence
- cloud RBAC-style scope evidence

This makes the data more reusable for labs and downstream tools because consumers can infer their own edges instead of inheriting pre-baked conclusions.
