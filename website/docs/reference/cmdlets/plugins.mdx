# Plugin Cmdlets

## `Get-SEGenerationPlugin`

Inspects plugins from one or more plugin root paths.

Key parameters:

- `-PluginRootPath`
- `-Capability`
- `-AllowAssemblyPlugins`
- `-RequirePluginHashApproval`
- `-PluginAllowedContentHash`

## `Test-SEGenerationPluginPackage`

Validates plugin packages before use.

This now includes pack-contract validation so plugin authors can check scenario-pack metadata and execution expectations before installation or CI use.

## `Install-SEGenerationPluginPackage`

Installs plugin packages from plugin root paths.

## `New-SEGenerationPluginPackage`

Creates a starter plugin package scaffold with the required manifest and baseline pack files.

## `Register-SEGenerationPlugin`

Registers plugin capabilities for reuse, storing the approved **content hash** of each one so it can be trusted later with `-UseRegisteredPlugins`.

The stored hash binds the built plugin, not its source. For a binary (`DotNetAssembly`) plugin the hash covers the manifest, the entry-point assembly, plugin-local data, and every file in the entry point's output directory — which includes the DataGen assemblies the build copies beside it.

:::warning Registrations do not survive a DataGen upgrade
Rebuilding a binary plugin against a different DataGen version changes its content hash, so every approved binary-plugin registration must be re-approved after an upgrade. Re-run `Register-SEGenerationPlugin` as part of taking the new version. See [Binary Plugin Guide](../../sdk/binary-plugin-guide.mdx#an-approval-pins-the-built-artifact-not-the-source).
:::

Script-plugin registrations are unaffected by a DataGen upgrade; their hash covers only the manifest, the script, and plugin-local data.

## `Get-SEGenerationPluginRegistration`

Lists registered plugin capabilities.

## `Unregister-SEGenerationPlugin`

Removes registered plugin capabilities.

## Plugin design reminder

These commands help you manage DataGen plugins, but the architectural rule still applies: plugins extend the synthetic dataset; they do not serve as downstream import adapters.
